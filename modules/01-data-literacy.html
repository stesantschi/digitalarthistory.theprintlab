Module 01

Data literacy for Japanese datasets

Names in a list: what each source decided before you opened the file.

  • ~60 min
  • no prerequisite
  • your own spreadsheet, or the example
  • CC BY 4.0

Outline. The worked example and its code are being prepared; this page gives the question, the steps and their limits.

The research question

Starting point

I have a spreadsheet of two hundred prints I gathered from four sources. Half the artist names don't match each other. How do I turn this into one list?

Almost every project starts here. Each mismatch records a decision someone made: how to romanise a name, which of an artist's names to use, whether a work has one maker or several. Different people made these decisions, in different institutions, for different purposes. Merging the list means choosing between them, and this module shows how to make those choices visible.

The Japanese material

Japanese names are written family name first. Western catalogues often reverse the order, usually without saying so.

Long vowels appear in four forms: with a macron (Ryōko), a doubled vowel (Ryouko), an h (Ohno), or unmarked (Ryoko). All four occur in real records.

Edo-period print designers also worked under art names (gō) and changed them during their careers. Hokusai signed as Shunrō, Sōri, Taito, Iitsu and others. These are separate names for one person, so no spelling rule will connect them.

The computational operation

A computer treats two names as the same when their characters are identical. A cataloguer identifies an artist by signature, seal, date and context.

This module translates the cataloguer's judgement into a form the computer can use, one decision at a time, and records what each decision leaves out.

What we will do

Open a messy list and see what it contains. Count the spellings of each name. Merge the ones that differ only in how they are written. Then build a concordance by hand for the names that are different but refer to the same person. That last part needs a person's judgement.

Step 1 — Open the file and look

Before changing anything, check what the file contains: which columns there are, how many rows, and how many cells are empty in each column.

The computational operation

Encoding is the way a file stores text as numbers. Modern files use Unicode. Older Japanese exports often use Shift-JIS.

If the wrong encoding is assumed, Japanese text turns into meaningless symbols: 文字化け, mojibake. Open the file again as shift_jis or cp932 before deciding it is damaged.

The encoding describes the institution's export system, not the print.

The columns already tell you something. A file with separate fields for the artist in Latin script and in Japanese script reflects a decision to treat them as two kinds of information.

How to read this

Empty cells usually cluster by source. One institution fills the Japanese-script field because it catalogues in Japanese; another leaves it empty because it transliterates on entry.

A count of empty cells therefore describes four cataloguing practices first, and your data second.

Step 2 — Count the spellings

List every form in which each artist's name appears, with how often it occurs. Then sort the forms into four kinds: differences of typing (capitals, spaces), of script (Latin or Japanese), of romanisation (Hokusai, Hokousaï), and different names for one person (Shunrō, Hokusai).

The Japanese material

Katsushika is a place name Hokusai adopted as a surname; Hokusai is the gō. Western catalogues pair them by convention, but he rarely signed that way.

A record giving only Hokusai still identifies him, because the gō is the identifying part. A record giving only Katsushika would not.

Step 3 — Standardise the spelling, and note what it costs

Standardising (normalising) makes names comparable by removing differences you have decided do not matter. Each such decision should be written down.

The computational operation

Normalisation applies one judgement to every row at once, and afterwards the differences it removed are no longer visible.

Unicode stores some characters in more than one form: full-width Ａ and half-width A look alike but are different characters. NFKC is a standard way of merging such forms. It goes further than most people expect: it also turns ① into 1.

Using it means stating that these differences carry no evidence in your material. That is often true, and worth saying explicitly.

Choice point

How far do you standardise? Each option removes something.

Spaces and capitals only
Safe and reversible, and it solves only the simplest cases. A good default for a dataset you will publish.
Add Unicode NFKC
Merges full-width and half-width forms, usually right for names. Apply it to the name column only, since it also changes other kinds of text.
Remove macrons and accents
Matches Ryōko with Ryoko, and also matches names that should stay apart. It discards information the cataloguer recorded on purpose.
Lowercase everything
Useful for matching, poor for display. Match on a lowercase copy and keep the original for display.

Always standardise into a new column and keep the original. The original is your evidence.

Step 4 — Build the concordance by hand

What remains are names that are genuinely different and refer to the same maker. Write a concordance with three columns: the name as recorded, the name you will use, and the evidence for the match (a signature, a seal, a reference work). The third column lets a reader check, and disagree with, each line on its own.

How to read this

The list of unmatched names is your working list, and it should shrink slowly. A concordance that matches everything on the first pass usually contains matches that are too generous.

Fuzzy matching scores how similar two spellings look. It will merge two different artists with similar names and miss that Shunrō and Hokusai are one person. Use it to suggest candidates, and decide each one yourself.

What this cannot tell you

  • Whether two names belong to one person. That is an art-historical judgement, based on signatures, dates, seals and the literature. The concordance records the judgement; you make it.
  • When a name changed. Knowing that Shunrō became Hokusai is one question. Knowing when, and so which prints fall on which side, is a separate one, and scholars disagree about it.
  • What was never recorded. If no source names the block cutter, the block cutter is missing from your analysis too, and the gap can look like a fact about Edo publishing.
  • Which source to trust. When two records disagree, the concordance makes you choose, and you are the one who has to justify the choice.

At the end you have two things: a list a computer can count, and a written record of every decision that made it countable. The record is what allows someone else to check your work.

Use your own materials

  1. Use your own export. Any spreadsheet or CSV file with a name column will do.
  2. Do steps 1 and 2 first. Counting the spellings usually shows how large the task is.
  3. Write your concordance from the spellings you counted, with the evidence column from the first line.

Keep the concordance as a file of its own. You can reuse it in every later project on the same material, and you can publish it: a documented concordance is a contribution others can cite.

What you should now be able to do
  • Open a file in an unknown encoding, and recognise the problem when the text arrives garbled.
  • Count the spellings of a name and sort them into four kinds: typing, script, romanisation, and different names.
  • Standardise into a new column, and say how far you went and why.
  • Write a concordance that records the evidence for each match, so that a reader can question a single line.
